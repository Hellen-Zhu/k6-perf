# 07 · 实战:切换到你自己的接口

前六章练的是语法和概念,这一章是把它们串起来,套到你真正要压测的接口上。

## 需要你提供的信息

在 [`template.js`](./template.js) 里我留了完整的骨架(涵盖 checks / thresholds / 自定义指标 / 数据参数化 / scenarios),但里面的目标接口、鉴权方式还是占位符。把下面这些信息发给我(或者直接自己填):

- **目标 URL**(比如 `https://api.example.com/v1/xxx`)
- **请求方法**及是否需要请求体(JSON payload,给个示例)
- **鉴权方式**——Bearer token / Cookie / API Key,以及怎么拿到(登录接口?固定 key?)
- **这个接口大概做什么**——方便设计贴近真实场景的 checks 和 thresholds(比如订单接口应该重点关注失败率而不是极致低延迟;搜索接口应该重点关注 p95 延迟)
- **合理的性能预期**——比如"p95 应该在 500ms 以内""失败率不能超过 0.5%"(如果暂时不知道,可以先跑一版拿到基线数据,再回头定数字,这是很常见的做法)

## 关于压测你自己接口时的注意事项

- **先确认你有权限压测这个环境**——如果是生产环境,务必和负责人确认压测时间窗口和强度上限,避免影响真实用户
- **从小往大加压**——参考 `03-stages` 的爬坡思路,不要一上来就打满预期峰值,先用极小的 VU 数确认脚本逻辑对,再逐步加压
- **thresholds 的数字要基于真实 SLA 或历史基线**,不要拍脑袋定一个"看起来合理"的数字

## 骨架文件

[`template.js`](./template.js) 已经包含:

- `BASE_URL` 走环境变量,方便切换测试环境
- `setup()` 预留了鉴权逻辑的位置
- 自定义 `Trend`/`Counter` 指标的位置
- `checks` 和 `thresholds` 的位置
- 一个 `smoke` + `load` 双场景的骨架(参考 `06-scenarios`)

拿到你的接口信息后,我会帮你把这些占位符换成真实逻辑。
